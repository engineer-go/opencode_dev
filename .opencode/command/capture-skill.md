Turn what this session taught into a reusable skill.

First load the `skill-authoring` skill with the skill tool and follow it.

Process:

1. Review the session for a class of work worth teaching: a non-trivial technique, a corrected workflow, a debugging path, a tool-usage pattern, or a user style or workflow preference. Skip one-off task narratives.
2. List the existing skills and prefer the earliest action that fits:
   - Patch a skill that was loaded this session or is in play, and covers the territory. Read it before editing.
   - Patch an existing class-level skill.
   - Add a `references/`, `templates/`, or `scripts/` file under an existing skill.
   - Create a new class-level skill only when nothing covers the class.
3. Read the target before editing. For a new skill, create `.opencode/skills/<name>/SKILL.md`, or the global `~/.config/opencode/skills/` for learnings that apply across projects.
4. Apply the authoring rules: procedure first, one rule per lesson, fix in place, no incident narration, and no environment, negative, or unresolved captures.
5. Do not edit skills that live outside this repo's control unless asked.

Report the skill name and exactly what changed, or state that nothing durable came out of the session.
